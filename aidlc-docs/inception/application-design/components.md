# コンポーネント定義

## フロントエンドコンポーネント（React SPA）

### FE-01: App
- **目的**: アプリケーションのルートコンポーネント。Redux Store のプロバイダーとフェーズルーティングを管理する
- **責務**:
  - Redux Store の初期化・提供
  - 現在のフェーズ（1〜4）に応じたページコンポーネントの表示切り替え
  - グローバルスタイル・フォントの適用

### FE-02: Phase1Page（虚飾の入力）
- **目的**: マッチングアプリ風フォームで「立派な自分」のプロフィールを収集する
- **責務**:
  - 自己紹介文・趣味・休日の過ごし方・理想の関係性・アピールポイントの入力フォーム表示
  - 入力バリデーション（空欄・10文字未満チェック）
  - 入力完了時に Redux Store へ保存し Phase 2 へ遷移

### FE-03: Phase2Page（本音の入力）
- **目的**: Phase 1 の虚飾に1対1対応した本音質問を表示し、実態を収集する
- **責務**:
  - `/generate-questions` API 呼び出しと結果の表示
  - Phase 1 の虚飾テキストを薄く表示しながら「これの本当のところは？」形式で質問提示
  - スライダー（定量）または自由記述（定性）の動的フォーム生成
  - ローディング状態の管理（5秒超でアニメーション表示）
  - 全回答完了時に Redux Store へ保存し Phase 3 へ遷移

### FE-04: Phase3Page（論理的否定）
- **目的**: AIによる「判決」を劇的な演出で表示する
- **責務**:
  - `/analyze` API 呼び出しのトリガー（Phase 2 完了時）
  - 画面暗転 → 2〜3秒無音 → 否定文浮上のアニメーション制御（Pure CSS）
  - 「AI裁判所が審議中...」ローディング表示（15秒タイムアウト考慮）
  - 否定文テキストの表示（法廷風文体）
  - Phase 4 への遷移ボタン（アニメーション完了後に有効化）

### FE-05: Phase4Page（改善案発行）
- **目的**: ダメなまま勝つ戦略と新プロフィール文を表示し、クライマックス演出を再生する
- **責務**:
  - ダメさ翻訳テーブルの表示（弱点 → 魅力）
  - 抹消線 → 上書きアニメーションの制御（Pure CSS）
  - 新プロフィール文（150〜300文字）の表示
  - 新ターゲット層の表示
  - 期待マッチング率（旧 vs 新）の対比表示
  - 新プロフィール文のコピーボタン

### FE-06: MonolithCharacter（AIキャラクター）
- **目的**: 無機質なモノリス（SF的・冷徹なAIイメージ）のビジュアルを表示する
- **責務**:
  - Phase 3/4 で表示されるAIキャラクターのビジュアル
  - フェーズに応じた状態変化（審議中 / 判決中 / 発行中）

## バックエンドコンポーネント（Python Lambda）

### BE-01: GenerateQuestionsLambda
- **目的**: Phase 1 の虚飾入力を受け取り、対応する本音質問リストを生成する
- **責務**:
  - API Gateway からのリクエスト受信・バリデーション
  - S3 からプロンプトテンプレートの読み込み
  - Bedrock（Claude Opus 4.7）への質問生成プロンプト送信
  - 生成された質問リスト（JSON）をレスポンスとして返却
  - エラーハンドリング（Bedrock タイムアウト・S3 読み込みエラー）

### BE-02: AnalyzeLambda
- **目的**: Phase 1/2 の対応ペアを受け取り、論理的否定文と改善案を生成する
- **責務**:
  - API Gateway からのリクエスト受信・バリデーション
  - S3 からプロンプトテンプレートの読み込み
  - Bedrock（Claude Opus 4.7）への分析プロンプト送信（矛盾検知 → 否定文 → ダメさ翻訳 → 新プロフィール）
  - 生成結果（否定文・翻訳テーブル・新プロフィール・マッチング率）をレスポンスとして返却
  - 匿名化データを S3 に保存（セッションID をキーに JSON 形式）
  - エラーハンドリング（Bedrock タイムアウト・S3 書き込みエラー）

## AWSインフラコンポーネント

### INFRA-01: API Gateway
- **目的**: フロントエンドからのHTTPリクエストを Lambda にルーティングする
- **責務**:
  - `POST /generate-questions` → GenerateQuestionsLambda へのルーティング
  - `POST /analyze` → AnalyzeLambda へのルーティング
  - CORS 設定（開発: `*` / 本番: CloudFront ドメイン）
  - リクエスト/レスポンスのログ記録

### INFRA-02: S3（データバケット）
- **目的**: プロンプトテンプレートと匿名化セッションデータを保存する
- **責務**:
  - `prompts/` プレフィックス：プロンプトテンプレート JSON の保存・読み込み
  - `sessions/` プレフィックス：匿名化セッションデータ（`{session_id}.json`）の保存

### INFRA-03: S3 + CloudFront（フロントエンドホスティング）
- **目的**: React SPA の静的ファイルを配信する
- **責務**:
  - React ビルド成果物（HTML/CSS/JS）の S3 保存
  - CloudFront による CDN 配信・キャッシュ制御
  - SPA のルーティング対応（404 → index.html リダイレクト）

### INFRA-04: Amazon Bedrock（Claude Opus 4.7）
- **目的**: 質問生成・矛盾検知・否定文生成・改善案発行のAIエンジン
- **責務**:
  - GenerateQuestionsLambda からの質問生成リクエスト処理
  - AnalyzeLambda からの分析リクエスト処理（矛盾検知 → 否定文 → ダメさ翻訳 → 新プロフィール）
  - リージョン: ap-northeast-1（東京）
