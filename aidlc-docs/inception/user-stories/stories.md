## Phase 1: 虚飾の入力

### US-01: 虚飾プロフィールの入力

**ストーリー**  
婚活疲れのユーザーとして、  
マッチングアプリで使っている「立派な自分」のプロフィールをそのまま入力したい。  
なぜなら、AIに現状を正確に把握してもらい、的確な分析を受けたいから。

**受け入れ基準**
- Given: ユーザーがサービスにアクセスした
- When: Phase 1 フォームに自己紹介文・趣味・休日の過ごし方・理想の関係性を入力する
- Then: 入力内容が保存され、Phase 2 へ進むボタンが有効になる
- エッジケース: 入力が空の場合、「入力してください」のバリデーションメッセージが表示される
- エッジケース: 入力が極端に短い（10文字未満）場合、「もう少し詳しく教えてください」と促す

### US-02: 入力フォームの使いやすさ

**ストーリー**  
婚活疲れのユーザーとして、  
マッチングアプリのような馴染みのあるUIで入力したい。  
なぜなら、違和感なく「いつものプロフィール」を自然に入力できるから。

**受け入れ基準**
- Given: ユーザーが Phase 1 フォームを開いた
- When: フォームを見る
- Then: マッチングアプリ風のデザイン（プロフィール写真プレースホルダー・項目ラベル）で表示される
- エッジケース: モバイルブラウザでも入力しやすいレイアウトになっている
- エッジケース: 各入力欄にプレースホルダーテキスト（例：「例：週末はカフェ巡りやジムでリフレッシュ」）が表示される

## Phase 2: 本音の入力

### US-03: 虚飾に対応した本音質問の表示

**ストーリー**  
婚活疲れのユーザーとして、  
自分が入力した虚飾の内容に対応した「本音」の質問を受け取りたい。  
なぜなら、何を告白すればいいか迷わずに済み、AIが的確な矛盾を指摘できるから。

**受け入れ基準**
- Given: ユーザーが Phase 1 の入力を完了した
- When: Phase 2 画面に遷移する
- Then: Phase 1 の各入力項目に対応した本音質問が生成・表示される（例：「週末はジムでリフレッシュ」→「実際の週末の過ごし方は？」）
- Then: Phase 1 の虚飾テキストが薄く表示され、「これの本当のところは？」という形式で提示される
- エッジケース: Bedrock の質問生成が5秒を超える場合、ローディングアニメーションが表示される
- エッジケース: Phase 1 の入力項目が少ない（1〜2項目）場合でも、対応する質問が生成される

### US-04: 本音の回答入力

**ストーリー**  
婚活疲れのユーザーとして、  
「AIにだけ教える」という安心感の中で本当の自分を入力したい。  
なぜなら、正直に答えるほど精度の高い分析が得られるから。

**受け入れ基準**
- Given: Phase 2 の本音質問が表示されている
- When: 各質問に対してスライダーまたは自由記述で回答する
- Then: 全質問への回答が保存され、Phase 3（分析）へ進むボタンが有効になる
- エッジケース: 定量化できる内容（頻度・度合い）はスライダー形式で表示される
- エッジケース: 具体的な実態を問う質問は自由記述形式で表示される
- エッジケース: 未回答の質問がある場合、「すべて回答してください」と促す

## Phase 3: 論理的否定（努力の剥奪）

### US-05: 暗転演出と否定文の表示

**ストーリー**  
婚活疲れのユーザーとして、  
AIによる「判決」を劇的な演出で受け取りたい。  
なぜなら、エンタメ性のある体験が「頑張るのをやめる」という心理的転換を促すから。

**受け入れ基準**
- Given: ユーザーが Phase 2 の入力を完了し、分析ボタンを押した
- When: Phase 3 の結果が表示される
- Then: 画面が暗転し、2〜3秒の無音の後、否定文テキストが浮かび上がるアニメーションが再生される
- Then: 否定文は「冷徹な裁判官」トーン（法廷風文体）で表示される
- エッジケース: Bedrock の生成が15秒を超える場合、「AI裁判所が審議中...」のローディング表示がある
- エッジケース: アニメーションが完了するまで次のフェーズへ進めない

### US-06: 学術的根拠付き論理的否定の受け取り

**ストーリー**  
婚活疲れのユーザーとして、  
「なぜ自分の戦略が間違っているか」を論理的・学術的に説明されたい。  
なぜなら、感情的な批判ではなく客観的な事実として受け入れることで、「頑張るのをやめる」決断ができるから。

**受け入れ基準**
- Given: Phase 3 の否定文が表示されている
- When: 否定文を読む
- Then: Phase 1 と Phase 2 の具体的な乖離が指摘されている（例：「被告は『ジムでリフレッシュ』を標榜しながら、実際の運動頻度は月1回と自己申告」）
- Then: 行動心理学・統計データ・進化学の3視点が均等に使われた学術的根拠が含まれる
- Then: 「もう頑張らなくていい」という宣告（努力の剥奪）が明示される
- エッジケース: 否定文が過度に攻撃的にならず、学術用語・統計用語で客観的事実報告として表現される

## Phase 4: 改善案発行（ダメなまま勝つ戦略）

### US-07: ダメさ翻訳と新プロフィール文の受け取り

**ストーリー**  
婚活疲れのユーザーとして、  
自分のダメな部分が「魅力」として翻訳された新プロフィール文を受け取りたい。  
なぜなら、すぐにマッチングアプリで使える具体的な成果物が欲しいから。

**受け入れ基準**
- Given: Phase 3 の否定文が表示された後、Phase 4 に遷移した
- When: 改善案が表示される
- Then: ダメさ翻訳テーブル（弱点 → 魅力への変換）が表示される（例：「ズボラ」→「一緒にいて楽な人」）
- Then: 新プロフィール文（150〜300文字）が生成・表示される
- Then: 新プロフィール文はダメさを隠さない文体で書かれている（取り繕った文ではない）
- エッジケース: 生成された文が300文字を超える場合、自動的に要約される

### US-08: クライマックス演出（抹消線 → 上書き）

**ストーリー**  
婚活疲れのユーザーとして、  
入力した虚飾の言葉が抹消され、新しい言葉に上書きされる視覚的な転換を体験したい。  
なぜなら、「古い自分の終わり」と「新しい戦略の始まり」を感情的に実感できるから。

**受け入れ基準**
- Given: Phase 4 の改善案が表示されている
- When: クライマックス演出が再生される
- Then: Phase 1 で入力したキラキラ言葉に抹消線アニメーションが引かれる
- Then: 抹消線の上に改善案のテキストが上書きアニメーションで表示される
- エッジケース: アニメーションはCSSで実装され、JavaScriptライブラリへの依存を最小化する
- エッジケース: アニメーションをスキップするボタンが提供される

### US-09: 期待マッチング率と新ターゲット層の確認

**ストーリー**  
婚活疲れのユーザーとして、  
新プロフィールの「期待マッチング率（市場適合性スコア）」と新しいターゲット層を確認したい。  
なぜなら、「ダメなまま勝てる」という戦略の説得力を数値で実感したいから。

**受け入れ基準**
- Given: Phase 4 の改善案が表示されている
- When: 期待マッチング率セクションを見る
- Then: 旧プロフィールの推定マッチング率と新プロフィールの推定マッチング率が対比表示される
- Then: 新ターゲット層の定義（年齢・属性・志向）が表示される
- Then: 新プロフィール文のコピーボタンが提供される
- エッジケース: マッチング率は「統計的推定値」であることが明示される（誇大広告防止）
