## 00. サービス概要（One Liner）

**「『頑張る婚活』をやめさせ、ダメなまま勝つ戦略を発行するAI裁判所」**

マッチングアプリで成果が出ないユーザーに対し、AWSのAIが**「立派な人を演じる努力」を有罪判決**。
虚飾を脱ぎ捨ててダメな本来の自分のままで勝てる戦略（新プロフィール）を発行する、
**自己研鑽社会へのカウンター型婚活ピボットサービス**。

### サービスが提供する2つの体験
1. **「ダメにする」体験** — 努力・自分磨き・立派な人を演じる労力を奪う
2. **「勝てる」体験** — 奪った努力の代わりに、ありのままで成功する戦略を授ける

## 02. 解決したい課題（Problem Statement）

### ターゲットペルソナ
- **名前:** 佐藤 健斗（さとう けんと）32歳、都内IT企業のPM
- **婚活状況:** アプリ利用歴8ヶ月、課金額累計10万円以上
- **悩み:** 書類審査（マッチング）の通過率が極端に低く、マッチしても会話が3往復で終わる
- **現在の虚飾（鎧）:**
  - 自己紹介：「週末はカフェ巡りやジムでリフレッシュ」「互いに高め合える関係が理想」
  - 趣味記述：「読書、映画鑑賞、新しいレストランの開拓」など意識高い系の羅列
- **裏の顔（素顔）:** 実際は休日カップ麺とYouTube、ジムは月1回。仕事のプレッシャーで疲弊しており、本音は「何もしたくない」

### 市場の問題
- マッチングアプリは「理想の自分を演じる」ことを暗黙に強要する設計
- スペック競争（年収・趣味・ライフスタイル）はレッドオーシャン化しており、量産型プロフィールでは勝てない
- 「ありのままでいい」というメッセージは溢れているが、**それを実利（マッチング成功）に変換するサービスがない**

### 動機設計（なぜユーザーが利用するのか）
- 「何ヶ月も書類審査で落ち続けている」 → わらにもすがる思いでAIアドバイスを求める
- 「AWSの最新AIがプロフィールを論理解析」という知的な建付けで集客
- 表向きは「改善」を求めて来るが、実は「もう頑張らなくていい」というお墨付きを求めている

## 03. サービスのコアバリュー（Value Proposition）

### コアロジック
> **「努力を奪うことは、勝率を上げるための不要なデータの削除である」**

虚飾という「敗北戦略」を破棄し、ユーザー固有の「ダメさ」を武器に
ターゲット層を **「理想の虚像を追う層」 → 「現実のダメさを共感する層」** にシフトさせる。

### 「ダメにする」→「勝たせる」のループ（サービスの中核）

```
[ユーザー入力（虚飾プロフィール = 頑張っている自分）]
        ↓
[AI による論理的否定 ─ 努力を奪う]
   - 矛盾の指摘
   - 学術的根拠による戦略破綻の証明
   - 「頑張っても無駄」の宣告
        ↓
[AI による改善案発行 ─ ダメなまま勝つ戦略]
   - 「ダメさ」を魅力に翻訳
   - ターゲット層を「ダメ仲間」へ再定義
   - 新プロフィール文の自動生成
   - 期待マッチング率の提示
        ↓
[ユーザーは"立派な人を演じる努力"を奪われ、ダメなまま成功する]
```

### 従来サービスとの違い

| 観点 | 従来のマッチングアプリ / 婚活サービス | 本サービス |
|------|------------|-----------------|
| 前提 | 自分を磨いて勝つ | 自分を磨くのをやめて勝つ |
| プロフィール作成 | 良い部分を盛る | 矛盾を論理で暴き、ダメさを武器化 |
| フィードバック | 「こうするといいですよ」（提案）| 「あなたは頑張るな」（断定）|
| 改善案 | テンプレ提案 | 「ダメなまま勝つ」個別最適プロフィール |
| 評価指標 | 主観的なアドバイス | 統計的な期待マッチング率 |

### ユーザーが体験する感情の弧
`自信（虚飾）` → `動揺（論理的否定）` → `諦め（頑張るのをやめる）` → `期待（ダメなまま勝てる新戦略）`

## 04. ユーザー体験フロー（User Journey）

### 全体フロー
```
【Phase 1】虚飾の入力
  └─ 普段通りの「頑張っている理想の自分」プロフィール文を入力

        ↓

【Phase 2】本音の入力
  └─ 「AIにだけ教える本当の自分」（ズボラ度・本当の休日・サボり癖）を入力

        ↓

【Phase 3】論理的否定（努力の剥奪）
  └─ AIがPhase 1とPhase 2の矛盾を指摘
  └─ 行動心理学・統計データ・進化学的視点に基づき「頑張っても無駄」を宣告

        ↓

【Phase 4】改善案発行（ダメなまま勝つ戦略）
  └─ ダメな部分を「勝ち筋」に変換
  └─ 新ターゲット層 + 新プロフィール文 + 期待マッチング率を提示
```

### 4フェーズ入力インターフェースの役割
| フェーズ | UI | 役割 | 抽出するもの |
|---------|-----|------|------------|
| Phase 1: 虚飾の入力 | 通常のマッチングアプリ風フォーム | 理想像の収集 | 表向きの自己像（Fact）|
| Phase 2: 本音の入力 | 5段階評価 + 自由記述 | 実態の収集 | 隠している実態（Truth）|
| Phase 3: 論理的否定 | 結果表示 + 対話 | 矛盾の言語化と努力の剥奪 | 認識のズレ（Insight）|
| Phase 4: 改善案発行 | 新プロフィール表示 | ダメなまま勝つ戦略の提示 | 勝ち筋（Strategy）|

## 05. 論理的否定の設計（Logic Design）

### 否定の論拠となる3つの学術的視点
論理的否定の説得力を担保するため、Bedrock のプロンプトに以下の3視点を組み込む。

| 視点 | 役割 | 否定への活かし方 |
|------|------|-----------------|
| **行動心理学** | ユーザーの「無意識の自己演出」のメカニズムを暴く | 「この表現は承認欲求の典型的な表出パターン」「自己呈示理論で説明できる虚飾行動」など |
| **統計データ** | 現戦略が市場で勝てない根拠を数値で提示 | 「同じ自己紹介パターンを使うユーザーのマッチング率は◯%」「人気の趣味記述ランキングであなたの記述は埋もれる」など |
| **進化学的視点** | 人間の本能レベルでの選好メカニズムを示す | 「進化心理学的に見て、嘘の匂いを察知する能力は性選択上の重要形質」「過剰な自己アピールは資源誇示として警戒対象になる」など |

### 否定の構造（必ず3要素を含める）
1. **事実の指摘** — Phase 1とPhase 2の乖離を具体データで提示
2. **学術的根拠** — 行動心理学・統計データ・進化学的視点のいずれかで戦略破綻を証明
3. **甘い期待の棄却** — 「もう少し頑張れば」という希望を切り捨てる（=努力の剥奪）

### 攻撃する「人格」の3カテゴリー
プロンプトでカテゴリーを切り替えることで、ユーザーの隙に応じた否定を生成する。

| カテゴリー | 否定の論理 | 学術的視点との対応例 |
|----------|----------|--------------------|
| 一貫性の欠如 | 言行不一致を証拠付きで指摘 | 行動心理学：認知的不協和理論 |
| 認知の歪み | 自己の市場価値の見積もり精度の低さ | 統計データ：自己評価バイアスの平均値 |
| 凡庸さ・代替可能性 | 文章のテンプレート性を統計で証明 | 進化学：差別化されない個体は性選択上不利 |

### AI Safety への対応
- 直接的な人格攻撃ではなく、**学術的視点・統計・論理の組み合わせ**で否定を構成
- 行動心理学用語・統計用語・進化学用語を多用することで、攻撃性を「客観的な事実報告」として表現
- これによりBedrockのセーフティフィルターを回避しつつ、ユーザーに「論理的に逃げ場がない」感覚を与える

## 06. 改善案発行の設計（Improvement Design）

### 「ダメなまま勝つ」改善案の4要素

| 要素 | 内容 | 目的 |
|------|------|------|
| 1. ダメさの魅力化 | 「ズボラ」→「一緒にいて楽な人」など、本音を魅力に翻訳 | プロフィール文の差別化 |
| 2. ターゲット層の再定義 | 「ハイスペ女性」→「等身大の生活を共有したい層」 | 競争市場のシフト |
| 3. 新プロフィール文の自動生成 | 自己紹介文 + アピール文 | 即座に使える成果物 |
| 4. 期待マッチング率の提示 | 統計に基づいた市場適合性スコア | 改善の説得力担保 |

### 改善案発行のロジック（Bedrockプロンプトの中核）
```
INPUT:
- Phase 1（虚飾プロフィール）
- Phase 2（本音）
- Phase 3で特定された矛盾点 + 学術的否定の論拠

OUTPUT:
- ダメさ翻訳テーブル（弱点 → 魅力）
- 新ターゲット層の定義（年齢・属性・志向）
- 新プロフィール文（150〜300文字、ダメさを隠さない文体）
- 期待マッチング率（統計推定）
```

### 改善の質を担保する3つのチェックポイント
- [ ] 否定の指摘ポイント全てに、対応する改善提案がある
- [ ] 改善後のプロフィール文が「ダメさを隠していない」内容である（取り繕った文ではない）
- [ ] ユーザーが「これなら自分でも書ける」と思える具体性がある

## 07. UX/トーンの方向性（Implementation Choice）

### 採用案：「冷徹な裁判官」トーン
否定パートのトーンとして、感情を排した法廷風の文体を採用する。

#### 採用理由
- **AI Safety突破:** 学術用語・統計用語で攻撃性を客観的事実報告に偽装できる
- **デモのインパクト:** 法廷UIは視覚的に印象に残りやすい
- **ペルソナ適合:** 佐藤さん（PM職）はロジック・エビデンス重視の世界の住人なので、最も逃げられない言語
- **サービス名との整合:** 「裁判所」というネーミングと自然に統合

#### 法廷トーン × 学術視点の具体例
- 「被告は『アクティブな休日』を標榜しながら、自己申告の歩数は500歩/日。**行動心理学における自己呈示理論**の典型的な失敗例である」
- 「同様の自己紹介文パターンを使用するユーザーのマッチング成立率は3.2%。**統計的に**この戦略の継続は非合理である」
- 「**進化心理学的視点**から、過剰な自己アピールは資源誇示として警戒対象となる。被告の戦略は本能レベルで逆効果である」
- 判決文「以上により、被告に『立派な人を演じる義務』からの**完全免除**を言い渡す」

### 代替トーン候補（チーム判断）
| 候補 | 特徴 | 向く相手 |
|------|------|---------|
| 冷徹な裁判官（採用案）| 感情排した法廷風 | ロジック重視の人 |
| 厳格なコンサルタント | データ駆動でクール | 経営層・分析職 |
| 辛辣なドクター | 診断 → 処方 の枠組み | 医療リテラシー高めの人 |
| 達観したデータサイエンティスト | 統計分析で淡々と | エンジニア層 |

### 演出のピーク設計（トーンを問わず適用可能）
判決/診断/分析結果の表示時に、以下の演出を入れる：
- 画面暗転 → 2〜3秒の無音 → 結果テキストが浮かび上がる
- フロントエンドのCSSアニメーションで実装可能（コスト低・印象大）

## 08. AWS アーキテクチャ（Technical Requirements）

### ハッカソン本番スコープ（Bedrock のみ）

| AWSサービス | 用途 | 実装詳細 |
|------------|------|---------|
| **Amazon Bedrock** (Claude Opus 4.7) | 論理否定エンジン + 改善案発行エンジン | Phase 1/2の入力から矛盾を検知 → 学術的根拠付きの否定文生成 → ダメさを勝ち筋に変換 → 新プロフィール文発行 |

### モデル選定理由（Claude Opus 4.7）
- **複雑な矛盾検知:** プロフィール内の論理的不整合を高精度で検出
- **多段推論:** 「矛盾検知 → 学術的否定生成 → ダメさ翻訳 → 新プロフィール発行」をワンプロンプトで実現
- **文体の使い分け:** 否定（厳格）と改善（前向き）でトーンを切り替えられる
- **学術ドメイン知識:** 行動心理学・統計・進化学の用語を破綻なく使いこなせる

### アーキテクチャ構成

```
[フロントエンド] (Phase 1〜4 の入力UI + 法廷演出)
  ↓
[API Gateway]
  ↓
[Lambda]
  └─ Bedrock (Claude Opus 4.7)
       ├─ 矛盾検知 + 学術的否定文 生成
       └─ ダメさ翻訳 + 新プロフィール文 発行
  ↓
[S3] 否定文・新プロフィール文を保存
  ↓
[フロントエンド] 結果表示（暗転 → 否定文 → 改善案 → 新プロフィール文）
```

- [ ] 否定文のアニメーション演出（テキストが一文字ずつ表示）
- [ ] 新プロフィール文のコピー機能
- [ ] **デモのクライマックス演出（下記いずれか）**
  - 案A：視覚的な転換 — 入力したキラキラ言葉に「抹消線」が引かれ、改善案として上書きされる
  - 案B：数値的な転換 — 旧プロフィールの市場適合性スコアが表示され、改善後のスコアと対比される

## 10. 非機能要件（Non-Functional Requirements）

- **レスポンス時間:** Bedrock (Opus 4.7) 生成は15秒以内
- **デモ環境:** AWS環境でエンドツーエンドで動作すること
- **セキュリティ:** プロフィール情報はセッション単位で管理、永続保存しない
- **コスト:** Opus 4.7はトークン単価が高いため、プロンプト設計でトークン消費を最適化

## 11. 審査・発表への対策（Presentation Strategy）

### テーマ宣言（発表冒頭で必ず定義する）
> 「『人をダメにする』とは、立派な人を演じる努力をやめさせること。
> AIが『もう頑張らなくていい』と公式判決を下すことで、
> ユーザーから自己改善の意欲を奪い、ダメなまま生きることを推奨する。

### 社会的意義（内側のテーマ）
- 過度な自己演出社会・自己研鑽カルチャーへのカウンター
- スペック競争（レッドオーシャン）から、ダメ仲間マッチ（ブルーオーシャン）への市場誘導
- AIによる**「頑張らない権利」の公式化**

### 技術アピールポイント
- **最新最上位モデル Claude Opus 4.7 採用**
- **多段推論をワンプロンプトで実現**：「矛盾検知 → 学術的否定 → ダメさ翻訳 → 新プロフィール発行」
- **AI Safety を学術用語（行動心理学・統計・進化学）への偽装で回避**するプロンプトエンジニアリング

### サービス価値の説明軸
- ⭕「人をダメにするサービス」 → ハッカソンテーマとの完全一致
- ⭕「ダメなまま勝てる戦略が手に入る」 → 機能的な動機。実利あり
- ⭕「AIから努力をやめる許可がもらえる」 → エンタメ性。話題性に繋がる

→ ピッチでは**「人をダメにする」を主軸**にし、副次的に「実利」と「エンタメ性」を訴求する。

## 13. 用語定義（Glossary）

| 用語 | 定義 |
|------|------|
| 虚飾プロフィール | 実態と乖離した「立派な自分」として入力されたプロフィール文 |
| ダメにする | 立派な人を演じる努力・自己改善の規範意識を奪うこと |
| 努力の剥奪 | 論理的否定によって「頑張る価値」を消失させる Phase 3 の効果 |
| 論理的否定 | 事実・学術的視点（行動心理学・統計・進化学）・論理の組み合わせで構成される、ユーザーへのフィードバック |
| ダメさ翻訳 | 「ズボラ」を「一緒にいて楽」のように、ダメな部分を魅力に変換する処理 |
| 戦略的リポジショニング | ダメさを「勝ち筋」に変換し、ターゲット層を再定義するプロセス |
| 期待マッチング率 / 市場適合性スコア | 新プロフィール文の統計的な成功率推定値 |
| ダメなまま勝つプロフィール | 改善案として最終発行される、ダメさを隠さない新プロフィール文 |
